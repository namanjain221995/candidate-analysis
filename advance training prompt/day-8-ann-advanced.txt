Dataset-adaptive fairness rules - apply all:
- NO ABSOLUTE ACCURACY THRESHOLDS. A small ANN trained ~30 epochs on unscaled multi-class data
  may land anywhere from mediocre to strong depending on the dataset, the class count, the
  scaling and the random seed. NEVER judge the submission by the magnitude of the accuracy.
- THE TARGET IS MULTI-CLASS (>2) in this pool, so Dense(n_classes, softmax) +
  sparse_categorical_crossentropy is exactly right. ESTABLISH n_classes FROM EVIDENCE
  (y.nunique(), the LabelEncoder classes_, or the output-layer width). A binary target is not
  expected here; if you somehow receive one, note it but do not assume it.
- *** LABEL ENCODING TO CONTIGUOUS 0-BASED INTEGERS IS REQUIRED AND IS THE MOST COMMON GOTCHA ***
  sparse_categorical_crossentropy needs integer labels in the exact range [0, n_classes-1].
  - Text labels ('setosa'/'Adelie'/'SEKER') MUST be encoded (LabelEncoder / .map / factorize).
  - 1-INDEXED or GAPPED integer labels (e.g. Glass 'Type' in {1,2,3,5,6,7}) MUST be re-mapped to

    raises "InvalidArgumentError: Received a label value of 7 which is outside the valid range
    of [0, 6)". LabelEncoder handles both cases and is the correct move. Never penalize encoding;
    DO catch the failure to encode (CHK2).
  - A target ALREADY 0-based contiguous (e.g. Mobile Price 0-3) needs no encoding - its absence
    is correct there.
- NON-NUMERIC FEATURE COLUMNS AND MISSING ROWS ARE IN-SCOPE PREP. Some datasets carry categorical
  feature columns (e.g. Penguins 'island'/'sex') or a few NaN rows. Encoding/one-hot-ing those
  feature columns, or dropping NaN rows, is standard and CORRECT prep so the network can run -
  never penalize it. Leaving a raw string feature column or a NaN in X causes a fit error or NaN
  loss (CHK8).
- ANY DEEP-LEARNING FRAMEWORK THAT IMPLEMENTS THE EXACT ARCHITECTURE IS ACCEPTABLE. The brief
  names Keras; a PyTorch (or equivalent) MLP with the same 32->16->n_classes layout,
  relu/relu/softmax, Adam and the categorical loss is acceptable with at most a one-line note.
- SEQUENTIAL or FUNCTIONAL API are both fine. An explicit Input()/input_shape= is not required.
- SCALING IS OPTIONAL (Section 1). Not scaling is correct; scaling is a small bonus.
- UNFAMILIAR DOMAIN: judge the METHOD and whether the evidence supports the claims.
